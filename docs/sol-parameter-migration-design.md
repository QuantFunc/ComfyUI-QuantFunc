## New and legacy contracts

New nodes use explicit Sol enable plus statistical tau (default 1.3). Absent/disabled Sol leaves the old dense/default behavior and sends no new key to an older engine. New enabled options serialize a `sol` object with tau, minimum tokens (default 12288), conditioning sink mode (default exact_kv_and_rows), and a `window` object with resolved sigma_start/sigma_end for default percentages 0.2/0.9. An explicit `sol_window_enabled` switch defaults true; false emits `window:null`, meaning genuinely unbounded/all-step activation, not finite percent_to_sigma(0/1) bounds. A window object requires both finite ordered bounds. Native API validates finite numbers and ranges; an enabled request on an engine without this object fails clearly rather than silently using legacy arithmetic. Advanced layer/profile/order options remain separate Sol-only settings; Morton is off by default and cannot be activated until the relevant model layout adapter is verified.

Add an optional serialized numeric `sol_version` marker (2 for new nodes), hidden with the existing hidden-widget technique used for model_config. Python loader signatures default this argument to None so an old API prompt without the marker still enters the legacy adapter; new UI prompts include the hidden marker. Saved graph properties also stamp `qf_sol_version=2`. Read the marker from the incoming raw configure payload, not the nodeCreated defaults, so old workflows cannot be mistaken for new ones.

For legacy video workflows, the old off epsilon `abs(value-1)<=1e-6` remains disabled; 0.25 is converted using the existing engine keep-ratio→statistical-threshold law, not interpreted as tau=0.25. Evaluate the old off epsilon before rounding, then round the old ratio to FP32 before conversion and the result to FP32 afterwards to match the engine boundary. The current UI's finite 0.02..1 range is the migration contract; explicitly test legacy API zero/default handling from the old residency_opts `or 1.0` behavior. Migrated workflows set sol_window_enabled=false (`window:null`) and min_tokens=0, preserving all-step activation even for custom schedules beyond nominal sigma_max; new workflows use the new defaults. The actual new FLOAT schema is min=-4, max=4, default=1.3: the negative extension preserves migrated keep ratios above 0.5 (0.75 becomes about -0.67449), without clamping. Repeated load/save must not convert twice. New version-2 tau=0.25 remains exactly a statistical tau=0.25.

Pin Python omission separately from widget defaults: loader signatures use sol_tau=None and sol_version=None. Marker-absent, tau-omitted old API resolves to legacy 1/off; version-2 tau omission resolves to 1.3 and requires explicit sol_enabled=true to engage. New-only Python arguments default to None so their presence without a version-2 marker is rejected as mixed/ambiguous input, not guessed. Unsupported versions, bool-as-version and nonfinite numbers are refused.

The legacy conversion is specifically `qfa_sol_keep_ratio_to_tau` in the engine worktree's `src/interop/qfa_attn_bridge.h:189`: after FP32 ratio conversion, compute p=1-ratio and retain its existing clamp to `[1e-4,1-1e-4]` before Acklam inverse-CDF evaluation and final FP32 conversion. This is not an uncapped NormalDist conversion. For example, active old 0.99999 maps to about -3.71901655, not -4.2646; the correct legacy outputs fit [-4,4]. “Do not clamp migration” above means no new clipping of the converted tau, not removal of the old law's probability clamp.

Bump the layout id from 2 to **3**. Add the current layout-2 positional orders to EARLIER: LTX `[transformer,model_config,attention_backend,sol_tau,step_cache,block_cache,quality_enhance,pinned_memory]`; H3 the same with audio_enhance after quality_enhance; Krea2/QwenImage21 `[transformer,model_config,attention_backend,quality_enhance,pinned_memory]`. Keep the older published/RC orders already present. Recover named values first; otherwise require a complete known positional shape. Use only markers actually present in the raw serialized payload: property qf_sol_version and named/recognized-current-shape sol_version widget. Neither marker means legacy; either explicit marker=2 establishes new semantics and inserts the missing peer marker; recognized conflicting markers or unknown versions are refused without mutation. A nodeCreated default is never evidence about an incoming old file. API prompts have only the explicit input marker, with the Python fallback above.

The browser first recovers old widget values by name or the known historical positional shapes, then transforms Sol values and constructs the new order. It must also recognize the immediately previous qf_layout=2 order, preserve model_config/API-key/custom widget values, and leave unrelated loaders/fields alone. Extend the existing layout stamp and tests; do not infer meaning from whether a number happens to be below 1.

## Runtime propagation

Add one normalized Sol options value and setter to QFSessionModelMixin, include it in `_SESSION_DIALS`, and copy its nested values when LoRA rebuilds adopt dials. Every loader applies it, including Krea2 and QwenImage21. `dial_opts` returns a fresh Sol dictionary and resolves sigma bounds through `self.model_sampling.percent_to_sigma`. No per-step GPU/CPU synchronization or new sampler wrapper is needed: the native step ABI already carries sigma. Disabling or omitting options must clear previous Sol state on a reused engine session.

Engine wiring is reviewed separately: a Sol-only settings value is stored per pipeline/transformer, transported through begin/t2i/t2v/update and reset, and evaluated from the actual step sigma and model layout. It must cover classic QwenImage plus QwenImage21 (the plugin's actual image loader), H3, LTX2 and Krea2. Do not claim plugin support from the classic QwenImage-only prototype test. Other sparse selectors and regional/cross-attention exclusions keep their current precedence.
